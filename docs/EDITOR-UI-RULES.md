# Editor 界面规范

这些约定来自用户反复指出的真实界面问题，修改同类入口时一起遵守。

## 布局和信息密度

- 信息密集的中文正文、字段和按钮使用 `oriel:sans` 12px 常规字重；不要把小点阵字放大或合成粗体作为默认中文排版。物品名称、说明和提示框按物品的原始字体与粗斜体预览。
- 扁平、紧凑，控件按内容占宽。不要卡片套卡片，不为一个字段做一整块大说明。
- 单控件卡片的选择按钮统一放在最右侧，复用同一套头部布局，不为不可见箭头或开关留空位。
- 交易使用玩家视角“你支付 → 你获得”；复杂编辑进入已有子页外壳，物品、数量和完整物品编辑就近放置，次数/经验/价格分组。
- 子窗口和浮层开、关都有动画；设置提供统一动画开关并持久化。关闭时同步释放焦点、ID 和监听器，退出动画不能让旧窗口接收输入或晚回包。
- 数字框在靠右布局和默认值读取期间也要保留可编辑宽度；不得用长占位文案挤掉数值，异步回显不能覆盖正在输入的文本。
- 数字输入外壳统一使用 `kStepper`，输入区宽度只在公共样式定义；页面不得单独缩短普通值或特殊浮点值的输入区。需要更多空间时调整外层排布。已知缺省显示“未设置”，仅真实请求未完成时显示“读取中”，请求失败单独显示。
- 仅含文字的详细编辑分段使用顶部标签，不得在窄布局隐藏全部文字后留下空目录栏；返回与编辑等动作不得被挤成残缺文字。
- 数字与增减、常用值就近放置；短的前后值直接排成 `4 → ∞`，不各占半行。只有内容确实放不下时才换行。
- 同类选择器共用已有组件；显示当前选择的名称和 ID，保留手输 ID。多选回显并按最终勾选同步，不能重复追加。
- 音效选择器的播放器统一放在列表下方、确认操作栏上方，横跨内容区域；字段行和列表项里不插入进度或重播按钮。保留原有播放/暂停按钮，暂停后再次播放默认从头开始。
- 播放进度在已有进度条上点击或拖动跳转，须实际改变声音播放位置；流式音频不能拿缓冲片段的长度当总时长。唱片名称由当前曲目注册表与语言包提供，没有名称时保留 ID。
- 可拖动分栏要有独立命中区域，与滚动条分开；保留两侧最小宽度，并记住用户调整。

## 文案和错误

- 所有常驻描述默认单行，放不下用省略号，悬停看全文；错误和代码不套用此规则。默认值与含义不重复解释，例如“默认 1”已足够，不再补“1 是原样”。
- 常驻说明只留操作所需的短句或数值。机制、实现细节、风险长文放点击/悬停后显示。不要用“数据完整保留、尚未确认、不冒充”等内部审计措辞填满界面。
- 游戏有对应翻译键或注册表译名时读取当前语言包，手写中文不能覆盖权威译文。没有原版键的字段说明作为编辑器文案维护；稀有度回退统一为“常见 / 少见 / 稀有 / 史诗”。不得虚构 i18n 键或将 NBT 原始标识改名。
- 上限必须给具体数字；联动必须给前后值，如 `生命上限：20 → 200`。不要让用户另去属性页找答案。
- 校验、读取和应用错误进入已有底部问题入口；不得在 3D 预览下另造一块警告。错误能换行、能查看完整内容，并在日志保留定位信息。
- 原版指令的特殊数值限制仅作简短提醒，不在提示里堆叠游戏模式、服务端条件或内部字段路径。首次复制提醒并将按钮改为“强制复制”，再次点击复制原文；内容变化后重新提醒，底部问题仍可点击跳转到对应设置。
- 需要再次确认才能继续的复制按钮，首次点击前就使用红色强提醒，“强制复制”也保持红色。复用 Ore 的 destructive 按钮纹理，正常、悬停和按下均有对应状态；普通复制不标红。
- `读取中`、`读取失败`、`Codec 拒绝`分开处理。刚打开尚未取得字段信息时，不能闪出“不支持”或假错误。

## 修改对比

- 恢复世界或玩家草稿后允许直接应用，不以阅读原始 SNBT 或点击“已比较”为前置条件；保留服务端的目标身份、权限与并发检查。
- 应用确认与高级改动对比共用字段级描述，只列确实变化的项。修改攻击伤害时不重复罗列没改的攻击速度。
- 常见示例：`攻击伤害 · 加成（主手） 4 → ∞`。修饰器 ID、原始数据和额外机制按需查看，不挤占短值。
- 特殊浮点值显示为 `NaN`、`∞`、`−∞`，常用值后提供实际 Codec 允许的快捷项。不再增加“特殊浮点值 · 不换算……”等常驻冗长说明。底层仍保留 Float/Double 的精确类型。

## 可编辑与实际生效

- 分清三件事：数据能否保存、游戏是否读取、最终会变成什么值。合法自定义数据不能仅因消费端有限制而被编辑器禁止。
- 例如桶可保存 `Health:100f`，某鱼放出时最多 3：允许编辑，短提示 `放出时：100 → 3`。桶的生物类型由物品决定，完整实体属性并不都由桶加载。
- 数值范围、能力、实体和物品候选来自当前游戏/Codec，不能手写一张物种表代替。未改字段、未知字段、long 和类型化数组必须保留。
- 新建列表里的子字段也可能带 typed Number。不能只查旧 AST 或父容器元数据；特殊浮点校验和应用必须走同一份 SNBT，防止 JSON 把 NaN/Infinity 变成 null。过期或错误格式的校验回执不能覆盖当前值的结果。
- 选中实体后就更新草稿前端名称、图标和面板，不要求再保存一次才显示；前端更新不能自动应用到游戏。

## 交付边界

更新日志面向玩家，沿用“新增 / 改进与修复 / 安装与兼容 / 已知限制”分类，说明具体操作与行为变化。BAT、Skill、构建、测试过程、源码冻结和实现审计放开发文档，不混进模组更新日志。尚未发布的修订标明待打包，未定位的问题不能写成已修复。

交付目录、包的集中摆放和选包步骤只写交付 README，不写游戏内更新日志。“安装与兼容”只记录依赖、支持版本或存档兼容性的变化；不能用它收纳打包安排。历史版本同样清理开发过程与验收统计。

游戏内日志从包内同一份 CHANGELOG.md 读取；在设置中按版本、日期、分类排列，默认展开当前版本，旧版本与分类可折叠。日志正文允许完整换行，不套字段描述的单行省略规则。交付时 Fabric 与 NeoForge 的六个目标 JAR 放在同一目录，并附玩家更新日志。

用户说“给我测试”时按上下文区分：要求体验 Sprite 等展示时，提供可粘贴的示例或场景供用户自行查看，不把它擅自扩大为执行测试。

按当前用户要求决定是否测试和打包。源码审阅、构建、独立原生验证和游戏实测分开记录。没有运行的明确标为未验证，不用一堆重复检查掩盖实际界面问题。
