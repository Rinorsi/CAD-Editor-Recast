# 剩余工作清单（P0 最容易 → P4 最难）

更新：2026-11-08 收工时。本文回答「明天做什么、先做哪个」。`PROGRESS.md` 是「做到哪了」的总表，`COVERAGE.md` 是 1.0 发布门槛，三者不冲突。

## 怎么读这份清单

- **分级按难度，不按重要性：P0 最容易，P4 最难。** 每一级里按建议的先后顺序排。
- **「验收」一栏：**
  - **自动** = 我能用 MCTest（驱动真实客户端）、`OrielAutomation` 探针、独立服务器探针、无头截图自己跑完并给出证据，不用问你。
  - **你** = 需要你的眼睛、手感或取舍（布局好不好看、动画顺不顺、要不要支持某功能），我只能把截图和对照准备好。
- **自动验收的范围有限：** 它能证明「点得开、写得进、读得回、没有报错、截图没有明显错位」，不能证明「好看」「顺手」。所有 ✅ 在你实机确认之前都不等于验收过。
- 每一项都标了来源，方便回头查。

## 明天开工前的固定动作

1. `git pull`，确认在 `main` 的干净基线（版本 0.99.2，今天已推送到 GitHub）。
2. 跑一条完整自动验收命令，确认基线是绿的，再开始新活：`pwsh -NoProfile -File tools/accept-all.ps1 -Full`。报告在 `logs/accept-all/<时间-id>/report.md` 和 `report.json`；参数、安全规则与阶段说明见 `tools/live-test/README.md`。日常快速档用 `-Quick`；只查界面用 `-Only ui`；预览不执行用 `-WhatIf`。
3. 你自己的游戏要**完全退出再启动**，否则读到旧的 Java 类。跑自动验收时不要开着自己的游戏（脚本发现用户游戏会自动跳过）。
