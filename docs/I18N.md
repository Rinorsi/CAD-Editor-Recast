# 编辑器多语言

语言文件位于 `common/src/main/resources/assets/cadeditor/lang/`。现有 `zh_cn.json` 与 `en_us.json` 的键必须对应，文字参数使用 `%1$s`、`%2$s`，字面百分号写成 `%%`。修改措辞时保留原键；新增文案优先取清楚、稳定的语义键。

扩展语言按 Minecraft 语言代码新增文件，例如 `ja_jp.json`、`fr_fr.json`、`de_de.json`。生成器自动发现这些文件，原生端也按所请求的语言加载同一路径，不需要修改语言名单。扩展文件可只翻译部分已知键，缺失条目回退英文；支持 `%s` 或 `%1$s` 参数。服务端提示使用服务端模组内的语言文件；客户端资源包的翻译用于界面与客户端提示。

前端用 `I18n.t(key, args...)`，原生用 `EditorI18n.tr(key, args...)`。页面在静态标签初始化前读取宿主的 `uiLocale`，默认预览为中文，未内置语言回退英文。宿主把当前资源包中与内置内容不同的编辑器译文传给页面，原生提示也优先使用当前游戏译文。

服务端请求入口通过 `EditorI18n.forLanguage(player.clientInformation().language())` 隔离玩家语言，包括单人内置服务器。新增独立服务器入口须建立同样的 try-with-resources 作用域；不能把玩家语言存成全局值。

关于页用 `I18n.en` 固定英文，异步复制回调给 `copyText` 传入 `en_us`。更新日志界面的加载、重试等提示仍可翻译，日志正文与分类直接读取中文 `CHANGELOG.md`。

`data.js` 是生成文件。编辑器自有字段说明由 `tools/i18n-data-fields.json` 显式绑定，生成时会核对路径和中文原文，避免误改用户文本及默认 NBT。游戏名称在实机中来自实时注册表，英文离线预览名称由实际 Minecraft 26.1.2 语言文件导出：

```text
python tools/i18n-vanilla.py path/to/minecraft-26.1.2.jar
node tools/i18n-sync.cjs
```

`tools/i18n-vanilla-en.json` 记录来源与原文件 SHA-256；它只供离线预览使用。更新基线后要重新生成并核对绑定，不把预览数据作为运行时游戏事实。

修改语言文件后运行 `node tools/i18n-sync.cjs`，提交同步生成的 `ui/js/i18n-catalogs.js`。构建会执行只读校验 `node tools/i18n-sync.cjs --check`，拒绝键缺失、参数不匹配、英文残留中文、绑定失效或生成文件过期。

针对性验证入口：

```text
node tools/ui-i18n-test.cjs
gradlew :fabric:26.3:i18nTest
```

这两项分别验证前端语言初始化、资源覆盖、英文关于与中文日志、用户 typed NBT 保真，以及原生参数格式和玩家语言隔离。编译、自动验证与游戏实测分别记录，不能相互替代。
