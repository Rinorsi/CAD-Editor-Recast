## 通用约束（所有 worker）

- 业务代码只写在 `common/`，不在 `fabric/`、`neoforge/` 里写业务；`common` 不得 import 加载器包。
- 游戏版本差异只用 Stonecutter，且记入 `docs/MULTIVERSION.md`。
- 可选数据来自游戏实时注册表 / Codec，不手写数据表；每个选择器必须允许手动输入 ID。
- 运行静默：隐藏窗口，不抢鼠标键盘，不碰用户已开的游戏实例。
- 全量实机验收只在全部做完时跑一次，开发中只跑编译和轻量测试。
- 每个里程碑 `git commit`（英文信息，结尾 `Assisted-by: Cindy (https://cindy.app)`），不 push。
- 每个新的服务端写操作都要过 `EditorPolicy` 的权限检查，并写进 `docs/permission-matrix.md`。

## P4-1 玩家（传送、重生点、配方书、成就、统计、离线玩家）

后端：玩家视图 / 写入契约，沿用世界编辑的「草稿 → 校验 → 服务端落地 → 回执」流程。
- 传送：当前维度坐标 + 朝向，跨维度需选维度（候选来自实时 `Level` 列表）；目标区块未加载时要先加载，失败给原因。
- 重生点：位置、维度、角度、是否强制；支持清除。
- 配方书：已解锁配方（候选来自实时配方注册表）、高亮标记；批量解锁 / 撤销。
- 成就：按进度列出，条件逐项可勾；只能改玩家自己的数据，写入走原版 `PlayerAdvancements`。
- 统计：只读 + 逐项改（候选来自实时 `Stats` 注册表）。
- 离线玩家：从世界存档的 `playerdata/<uuid>.dat` 读写，**仅当该玩家不在线时**；在线则拒绝并提示。
  写入前备份原文件（保留最近 N 份），原子替换，校验失败不落盘；要有 game master 权限，单人世界和专用服务器都要考虑。
  身份保护：不能借此改自己以外的玩家，除非有权限；操作写日志。
- 测试：服务端探针覆盖每一项的读、写、拒绝路径；离线玩家要测备份、原子性和并发（玩家此时上线）。

前端（Claude）：玩家页新增「位置」「配方」「成就」「统计」标签和离线玩家入口，照现有 UI 规范。

- 冲突规则：同名不覆盖，改为「新增一份并加序号」；套用前显示将被覆盖的内容摘要。
- 离线合并脚本 `tools/vault-persist/merge-legacy.ps1` 要认新类别。
- 测试：存入 → 重开 → 套用的往返相等；类型不符被拒；权限不足被拒。

## P4-4 模组方块 / 实体 / 组件的通用适配

不逐个模组适配（模组太多），而是按「模组总要注册」这一点做通用机制：
- 组件：本来就按 `data_component_type` 注册表和各自 Codec 在运行时生成表单，模组组件应已自动覆盖；
  要用一个带假模组注册的探针验证：新注册的组件类型能出现在候选里，能增删，能往返保存。
- 方块实体 / 实体：遍历 `block_entity_type` / `entity_type` 注册表，对每个类型建一个默认实例，
  保存一次得到它的 NBT 形状，据此推断字段类型（整数 / 浮点 / 布尔 / 字符串 / 列表 / 复合 / 物品栈 / 方块状态 /
  注册表 ID，ID 的判断依据是该字符串能否在某个已知注册表里命中，不能靠名字猜），生成带类型的通用表单。
  任何推断不确定的字段退回 SNBT 编辑，并保证往返保存不丢字段、不改类型。
- 已有的专用视图优先；通用表单只补没有专用视图的类型。
- 测试：用一个测试用模组（在 testFixtures 里注册一个自定义方块实体、实体和组件）覆盖读、改、保存、重开。
- 这是一个尽量适配的机制，不承诺所有模组完美；覆盖不到的在界面上明确显示「这个字段只能在数据页编辑」。

## 分发流程

- 版本号一处定义（`gradle.properties`），`tools/bump-version.ps1` 同步更新 README、CHANGELOG、模组元数据。
- `.github/workflows/`：矩阵构建六个 jar + 单元测试 + codecVerification；打 tag 时产出 Release 附件和 SHA256。
- `CHANGELOG.md`、README 里的「下载 / 安装 / 支持的版本」表、模组元数据里的 Modrinth / CurseForge 字段（id 留空，由用户填）。
- 内存短时采样：在验收里加一段 N 分钟的客户端内存采样，记录峰值和增长，超阈值报警。
