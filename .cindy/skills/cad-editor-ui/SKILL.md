# CAD Editor 界面修改

先读 [项目界面规范](../../../docs/EDITOR-UI-RULES.md)。它是本项目这些规则的权威正文，避免在各个控件里重新解释一套。

- 沿用已有控件与统一问题入口；改公共入口时检查它的物品、世界和嵌套编辑调用方。
- 游戏术语先用当前语言包和实时注册表译名；不能用手写中文覆盖它。没有原版键的字段说明明确按编辑器文案维护，统一回退术语见界面规范和 docs/LOCALE-AUDIT.md。
- 直接呈现用户操作涉及的具体值。确认框只列真正变化的字段，短值使用紧挨着的“原值 → 新值”。
- 常驻文案保持短句。机制解释、实现细节、原始错误和长规则放按需展开的现有提示/问题入口。
- 区分数据可存储范围与游戏实际消费范围：不因放出时被限制就禁止合法自定义 NBT，也不宣称保存成功就已在玩法中生效。
- 数值校验、预览、草稿、导出和应用必须识别同一份 typed 数据；NaN/Infinity 不得单独经过会转成 null 的 JSON 通路。字段信息未到不能判不支持。
- 用户给出新截图时，先按截图纠正当前布局或行为；不要只改一段文案，也不要新增另一套入口。
- 验证规模依改动风险和当前授权决定。用户明确不测、不打包时，只做源码修改与阅读，标明尚未验证；不要偷偷启动游戏、Gradle 或全量测试。

完成后说明实际改了哪些、哪些尚未验证。不要用旧包、旧实机或其他执行通道的结果为本次修改背书。
